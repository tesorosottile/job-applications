# Proposals

Written by the monthly retro. **Read by me, merged by me, never applied automatically.**

One file per retro: `YYYY-MM-DD.md`.

## Reviewing a proposal

Ask in this order:

1. Does it touch a FROZEN path? → reject, and note the retro is drifting.
2. Is the evidence at least 3 instances, cited? → if not, reject.
3. Is it encoding something I actually corrected repeatedly, or is it the system tidying
   itself? → only the former is worth merging.
4. What does it cost if it's wrong? → the retro must have answered this. If the answer is
   "letters get worse in a way I won't notice", weight that heavily.

## After merging

Apply the edit yourself, then add a line to the changelog at the bottom of the file you
edited: date, what changed, which proposal it came from. Without that, six months from now
you won't be able to tell why a prompt says what it says.

## Keep the rejections

Don't delete proposal files you rejected. A retro that proposes the same rejected thing three
times is telling you something — either about the retro, or about a real problem you keep
declining to fix.
